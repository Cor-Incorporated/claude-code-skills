# Slack の下書き（画面で確かめるまで「できた」と言わない）

相手に送る文を下書きとして用意する。送信はユーザーがする。**下書きが本当に Slack の入力欄に入っていることを、画面で確かめてから報告する。**

## Critical：2026-11-13 に実際に起きたこと

| # | したこと | 起きたこと |
|---|---|---|
| 1 | `slack_send_message_draft` を2回呼び、2回とも `Draft created` が返った | チャンネルの入力欄は**最初の下書きのまま**で、「下書き＆送信済み」も1件だけだった。API の返事を信じて「作り直しました」と2回報告した |
| 2 | 本文に「添付のメモにまとめています」「アジェンダを添付します」と書いた | 下書きにファイルは付けられない。相手が開いても何もない |
| 3 | リンクを Slack の書き方 `<URL\|文字>` で書いた | 下書きでは表示されず、相手には URL が見えない |

原因：API の返事を「入力欄に入った」ことの証拠にした。1つのチャンネルに入る下書きは1つだけで、ユーザーがその下書きを手で直していると、API で作った下書きは入力欄に出てこない。

## 手順

### 1. 先に入力欄の今の状態を見る（毎回）

Claude in Chrome（なければ内蔵ブラウザ）で、対象のチャンネルを開く。

```
https://app.slack.com/client/[チームID]/[チャンネルID]
```

- `get_page_text` で入力欄の文と、左の「下書き＆送信済み」の件数を読む
- 開いた直後は白い画面のことがある。数秒待ってから読む

### 2. 入力欄に下書きがあるとき：画面の上で直す（API で新しく作らない）

1. ユーザーが手で直した部分は残す。自分が前に書いた版と比べて、変わっているところは消さない（例：「確認させていただきました」に直してあった）
2. 右下の表示を確かめる
   - 「Return で改行」なら、Return キーで改行になる
   - 「Shift + Return で改行」なら、改行には `shift+Return` を使う
   - **送信ボタン（紙飛行機）は押さない。`cmd+Return` も押さない**
3. 書き換える範囲を選ぶ：その行をクリック → `cmd+Left` → `shift+cmd+Down`（最後まで）。スクリーンショットで選ばれた範囲を確かめる
4. `Backspace` で消して、**まず2行だけ**打つ。スクリーンショットで、改行になったこと・チャンネルに新しいメッセージが出ていないことを確かめる
5. 残りを打つ

### 3. 入力欄に下書きがないとき

`slack_send_message_draft` で作ってよい。そのあと必ず手順1で入力欄を読み、文が入っていることを確かめる。入っていなければ、手順2のやり方で画面に打つ。

### 4. ファイルは「添付」と書かず、URL で渡す

- ファイルは、相手が見られる共有フォルダ（Google Drive など）に置く
- `get_file_permissions` で、**相手のメールアドレスが権限の一覧にあること**を確かめる
- 本文には、ファイルごとに **URL をそのまま1行で**書く
- 「添付します」「添付の」は書かない。本当にファイルを付けた投稿のときだけ使う

### 5. リンクの書き方

- URL はそのまま書く（`https://...` を1行に）。入力欄で青いリンクになる
- `<URL|文字>` や `[文字](URL)` は使わない（下書きで表示されなかった）
- 6本以上あると、プレビューは最初の5本しか出ない。リンク自体は押せる

### 6. 報告の前に確かめること（全部そろうまで「できた」と言わない）

- [ ] `get_page_text` で読んだ入力欄の文に、入れるはずの URL が全部ある
- [ ] 「添付」が残っていない（実際に付けていないとき）
- [ ] スクリーンショットで、URL が青いリンクになっている
- [ ] チャンネルに自分の新しいメッセージが出ていない（送っていない）
- [ ] 「下書き＆送信済み」が何件か

報告には、入力欄から読んだ文の最初と最後の行と、「送信していない」ことを書く。API の返事（`Draft created`）だけで「作った」と書かない。

## うまくいかないとき

| 状況 | すること |
|---|---|
| Slack にログインしていない画面になる | ユーザーにログインしてもらう。パスワードは入力しない |
| 入力欄が見つからない／文字が打てない | 下書きの全文をチャットに出して、ユーザーに貼ってもらう |
| 書き換えの途中で送ってしまった | すぐにユーザーに伝える。消すか直すかはユーザーが決める（勝手に消さない） |
| ブラウザが使えない | 全文をチャットに出し、「入力欄はまだ確かめていない」と書く |
