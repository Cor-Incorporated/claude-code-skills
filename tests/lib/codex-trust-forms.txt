# Spellings of one [hooks.state."..."] trust entry, and what each side makes of them.
#
# Row: label|codex|reporter|config.toml
#   codex     what Codex does with the probed hook (CLI 0.156.0, 2026-09-25):
#               runs    - enabled, and trustStatus trusted
#               skips   - listed, but disabled or not trusted: skipped SILENTLY
#               rejects - config.toml does not load at all
#   reporter  what hooks/lib/codex-trust-state.py prints for the probed hook:
#             quiet, or the reason it gives in parentheses
#   config    the whole config.toml. Escapes \n \t \r only; placeholders
#             @K@ = the probed hook's trust key, @H@ = its trusted hash
#
# The probed hook is PreToolUse 0:0. A SessionStart hook without any entry is
# registered next to it as a sentinel, so every run must print at least one line.
#
# tests/test-codex-trust-state.sh checks the reporter column (CI).
# tests/test-codex-trust-conformance.sh checks the codex column against the real
# binary (local only; CI has no codex CLI). Together they tie the reporter to
# Codex: quiet appears exactly on the rows where Codex runs the hook.
# CI cannot tell a wrong codex column from a right one, so run the conformance
# test whenever a row is added or changed, and after every Codex upgrade.
#
# Not listed: a trusted_hash that no longer matches the hook (Codex: modified,
# skipped) and an entry for another hooks.json at the same position. The reporter
# cannot tell either from a valid entry, so it stays quiet on both.
